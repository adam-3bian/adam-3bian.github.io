# Outstanding scenery and route work

The user has reported glitches with road bridges and scenery beside the track. Exact locations have not yet been supplied, so these observations and the historical audit do not identify every visible defect or prove that a particular bridge is correct. The next implementation should reproduce them from the front view, record location and direction, and compare them with the supplied frames and maps.

| Area | Current evidence and outstanding work |
| --- | --- |
| Road and rail bridges | Some bridge-road profiles use inferred clearance and approach blending, and generic bridge assemblies are placed for inferred crossings. Source-defined structures are also used. The earlier audit did not certify every bridge's opening, underside, foundations, road approaches, skew or continuous intersections. Inventory each bridge, review it against its source and check that the road, deck, piers, railway and surrounding terrain connect without floating, clipping or blocking the lower route. |
| Trackside scenery | Existing front-view captures show very simplified buildings and sharply faceted embankments; some station compositions are inferred. Check trackside slopes, retaining walls, fences, vegetation, building bases, ballast shoulders and chunk joins against the frames in both directions. Faceting itself is intentional; unsupported, intersecting or implausible geometry is not accepted. |
| Road and asset support | The previous 121-tile audit recorded **574 unmatched same-level road-surface samples**, **187 rejected building-instance records** and **843 unsupported cable-attachment candidates**. These are gaps or unresolved coverage, not a count of confirmed visible glitches. Resolve or document each by ID; do not make the totals disappear by suppressing checks. See [geometry.json](reports/geometry.json) and [SOURCE-GAPS.md](SOURCE-GAPS.md). |
| Stations and landmarks | Nine station compositions use inferred fallback layouts; architecture, access routes, skyline forms and many facilities need location-by-location reference matching. Three independent local reviews have not yet established the requested recognition targets. |
| Track and operations | Some western point identities and complex eastern layouts are unresolved. Signals, speed sections, services and crossing details are representative simulator authoring rather than a verified current operating plan. More point routes and route locking need implementation and testing. |
| Other incomplete assets | The catalogue identifies incomplete or non-exhaustive site-specific equipment, including some drainage and yard equipment, lifts/subways, viaducts/culverts, car parks, operational signs, articulated lorries and cyclists. Door-side animation and passenger boarding also remain incomplete. See [ASSET-CATALOGUE.md](ASSET-CATALOGUE.md). |
| Traffic, performance and stability | Road priorities and lane connections need further validation; the full mixed-traffic scenario, two-hour browser soak and declared hardware performance benchmark are still outstanding. Lowering render resolution can reduce GPU pixel work, but cannot by itself resolve CPU-heavy scenery generation, draw calls, streaming or geometry defects. |
| Verification scope | The previous WebGL browser run captured eight stations in both directions, not the whole route. The full geometry report is a sampled CPU audit, with the unsupported and unmatched cases above; it is not continuous whole-world clearance or visual certification. See [ACCEPTANCE.md](ACCEPTANCE.md) for the measured snapshot and remaining gates. |
